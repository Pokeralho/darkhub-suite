# Contributor kit

Material to bring the first outside contributors to DarkHub Suite. Nothing in this folder has been published: every
step that touches GitHub or a social network is for the owner to run.

## What is here

| File | What it is |
|---|---|
| [issues/](issues/) | 18 ready issue drafts (translations, packages, tests, UI, accessibility, performance, optimizer, docs). Each has front matter with title and labels, then context, what to do, files, how to test and definition of done. |
| [create-issues.ps1](create-issues.ps1) | Creates the missing labels and the 18 issues with the GitHub CLI. Skips titles that already exist, turns relative links into GitHub links. `-ParseOnly` and `-DryRun` change nothing. |
| [LAUNCH.md](LAUNCH.md) | Drafts for Show HN, r/pcmasterrace, r/OptimizedGaming, r/Windows11, Brazilian communities, a pitch for YouTubers, and the repository setup checklist. |

Related files changed or added as part of this kit:

- `README.md`: "Why DarkHub needs administrator rights" section, Contributors section, link to the Portuguese README
- `README.pt-BR.md`: full Portuguese version of the README
- `.github/CONTRIBUTING.md`: "Contribute without the native toolchain" and "Good first contributions"
- `.github/ISSUE_TEMPLATE/`: `bug_report.yml`, `feature_request.yml`, `package_submission.yml`, `config.yml`
- `.github/PULL_REQUEST_TEMPLATE.md`: checklist
- `.gitattributes`: generated folders marked `linguist-generated` so GitHub shows the repository as TypeScript, not HTML
- Root cleanup: `CONTRIBUTING.md` and `SECURITY.md` moved to `.github/` (GitHub still finds them there), `DESIGN.md`,
  `TRANSLATIONS.md`, `AGENTS.md` and `SECURITY_RULES.md` to `docs/`, `CLAUDE.md` to `.claude/`, the release scripts to
  `scripts/`; `graphify-out/` is no longer versioned (generated by `npm run map`)

## Order to do things in

1. **Review and commit** the kit (README, CONTRIBUTING, templates, `.gitattributes`, this folder). The old
   `.md` issue templates were already removed in favor of the `.yml` forms.
2. **Push to `main`.** After the push, check that the language bar on GitHub shows TypeScript/JavaScript (it can take a
   few minutes to recompute).
3. **Repository settings** (see LAUNCH.md §5): enable Discussions and create the categories; enable private
   vulnerability reporting; add the topics.
4. **Create labels and issues:**
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File docs\community\create-issues.ps1 -ParseOnly
   powershell -NoProfile -ExecutionPolicy Bypass -File docs\community\create-issues.ps1 -DryRun
   powershell -NoProfile -ExecutionPolicy Bypass -File docs\community\create-issues.ps1
   ```
5. **Publish a release** if the current one is old, so people who arrive from the posts get the latest version.
6. **Post**, one place at a time, over one or two weeks: Show HN first (technical feedback), then r/OptimizedGaming,
   r/Windows11, r/pcmasterrace, then the Brazilian communities. Reach out to YouTubers after the first round of
   feedback is fixed.
7. **Keep pull requests moving**: review them within a few days.

## Keeping the kit current

- When an issue is solved, write a new one in `issues/` with the same structure and run the script again (it only
  creates titles that do not exist yet).
- Paths in the drafts were checked against the code when they were written; line numbers can drift, so the drafts
  mostly name functions instead.
